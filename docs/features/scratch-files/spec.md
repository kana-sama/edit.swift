# Scratch files

Save the current editable document as a scratch and return to it later from the sidebar or Go to File. A scratch is a persistent text document in Edit’s storage. It is global or associated with one folder.

## Save as a scratch

- **File → Save as Scratch…** follows **Save As…** and is also available in Command Mode. It opens a dedicated AppKit sheet for any editable buffer, including an untitled draft, a named file, or an existing scratch.
- Use the compact native Save layout with two controls. **Save As** is a focused filename field with the basename selected. It starts with `Untitled.txt` for an untitled document or the current name otherwise. **Attach to** offers **Global**, the window’s [folder](../folders/spec.md), recent folders, folders already used by scratches, and **Choose Folder…**. The default is the window’s folder or **Global** in a folderless window. Distinguish duplicate folder names by path. **Choose Folder…** opens the native directory picker. Cancelling the picker keeps the previous category.
- **Save** or Return writes the current text using the current encoding, BOM, and line endings, then continues editing the saved scratch in the same window with its selections, scroll position, undo history, and folder context. The original named file or scratch remains available at its own path. If the name is already in use in the selected category, add the first available numeric suffix before the extension, starting at `2`.
- **Cancel** or Escape closes the sheet without creating a scratch. While a write is pending, keep the sheet open and prevent repeat submission. If the name is invalid or saving fails, show the error in the sheet and preserve the document and both inputs for retry.
- For an untitled document, place a native **Scratch** button to the right of the encoding menu and center it vertically in the same row in both the Save panel and the [untitled close sheet](../files/spec.md#new-close-and-restore). Use the system panel’s [accessory view](https://developer.apple.com/documentation/appkit/nssavepanel/accessoryview). Clicking **Scratch** saves directly using the entered name and selected encoding. Associate the scratch with the window’s project or use **Global** in a folderless window. With **Command-S**, continue editing the saved scratch. When closing or replacing a document, continue the pending action after a successful write. If the write fails, show the error and keep the editable draft.

## Storage and editing

Record pending file changes before creating, importing, trashing, or restoring scratches. The next read after an interruption reconciles those records with the files that reached their destination. Files moved into the system Trash stay there. Scratch metadata already in the index remains available for files still in storage.

- Keep scratch contents and their folder associations under `~/Library/Application Support/dev.edit-swift.Edit/Scratches/`. Each scratch has a stable identity and belongs to exactly one category. The folder association persists as a path, including when the folder is unavailable. Folder aliases that resolve to the same directory share a category.
- Open a scratch as a regular editable document in the current window, with the existing draft protection when replacing the current buffer. Opening it preserves the window’s folder context. The scratch remains available after the window closes or Edit restarts. Restore scratch documents and any unsaved edits through the existing session rules.
- Apply [autosave](../autosave/spec.md) to scratch edits, including the one-second idle trigger, focus loss, and the flush before replacing the buffer, closing, or quitting. On a write failure, preserve the edits through the existing prompt and draft recovery. **Save As…** saves a regular file and continues editing at its chosen path. The saved scratch stays in its category.
- Scratch files are discoverable through **Scratches** and **Go to File**. They stay out of **Open Recent**, the project’s Worktree, and the folder’s remembered-file slot.

## Scratches sidebar

- Place **Scratches** immediately below **Worktree** in the [sidebar title menu](../sidebar-menu/spec.md). It is available with or without a folder open. When opening the sidebar for a window with no remembered mode, show **Scratches** if no folder is open and **Search** if a folder is open. ⌘B and session restoration remember the last mode, including **Search**. ⌘F switches to Search.
- **View → Focus Scratches** (Shift-Command-W) shows the sidebar and focuses its outline. Press it again while the outline has focus to focus the current buffer and keep Scratches visible.
- Use the native [Worktree outline](../worktree/spec.md). Show **Global**, the window’s current project, and other folders with scratches as expandable categories. Order the folders by name and path after Global. Distinguish identically named folders by path, and order files within a category by name. Keep Global and the current project as available destinations when empty.
- A primary click or Up and Down open the selected scratch in the current window while keyboard focus stays in the outline. Use Command-click and Shift-click to select multiple rows. A single primary click on a category row or its disclosure chevron toggles the category. Space opens the selected file if needed and focuses its buffer, or toggles disclosure for a category. Return edits a file’s name in place. When a scratch opens through ⌘P or another entry point, reveal its category and select its row without taking focus from the editor. Opening a selected scratch from the tree preserves its multiple selection.
- Reuse the Worktree file context actions for revealing the backing file in Finder, Open With, Copy, Copy Path, inline Rename, and Move to Trash. Category menus offer **New File…** and Paste for plain-text files. Categories represent folder associations. The outline lists every scratch in its category, including names that start with a dot. Undo and Redo reverse scratch renames, category moves, and Trash operations.
- Drag one scratch or a selection onto a different category to move it. Option-drag copies. Dragging out provides ordinary file URLs, and dropping readable text files from other apps copies them into the destination category. **Move to** also accepts **Global**, the listed folders, and **Choose Folder…** for a destination that has yet to appear in the tree. Cancelling the picker or choosing the sole source category leaves the association as it was.
- A move changes the association of the same scratch, preserving its contents, open editor state, and pin. For a duplicate name, apply the same numeric suffix rule as on first save. After success, update the outline and Go to File. A category with no remaining scratches disappears when it represents neither Global nor the current project. If the move fails, show the error and preserve the original associations.
- When a folder is renamed, moved, or unavailable, keep the old category and its scratch files accessible. Select the new folder through **Choose Folder…** to reassign a scratch to it.

## Go to File

- ⌘P includes all scratches associated with the window’s active folder. With no folder, it includes all global scratches. Apply this scope to pinned scratches too. The sidebar provides access to every category from any window.
- With an empty query, show pinned items first in their saved order. Then show recent scratches and ordinary files together, newest first. Successfully opening, restoring, or first saving a scratch updates its recency across launches. Ordinary Save, autosave, and changing a scratch’s category leave its position alone. Search matches all eligible scratches by filename and displayed folder or **Global** label, including scratches without recent history. Rank them with other files by fuzzy score, then recency. An explicit subdirectory query keeps its ordinary filesystem scope.
- Show a **Scratch** status icon in the row’s trailing area immediately to the right of the pin icon when present. Show it on unpinned scratch rows too. Expose the status to accessibility and retain the normal leading file icon. [Pinning](../control-pins/spec.md), navigation, and opening work as on other file rows.
- If loading the list or opening a scratch fails, report the error and keep the current editor available. In Go to File, keep the query and selected row available for retry.

## Acceptance

- Open **Save as Scratch…** from File and find it in Command Mode. Verify the two fields, focus on the basename, default **Global** in a folderless window, and default folder in a folder window. Select another folder and cancel once, then save. Check that the saved scratch is editable in place and is listed under the selected folder.
- For an edited untitled buffer, open **Command-S** and the close sheet. Check **Scratch** beside the encoding menu in compact and expanded layouts and verify that the Tags field is hidden. Enter a name and use **Scratch** in each sheet. Verify the name, encoding, project or **Global** association, and that the requested close waits for the write. Try an invalid name and verify the draft stays open. Check that ordinary **Save**, **Delete**, and **Cancel** retain their actions in the close sheet.
- Save a named file as a scratch with an existing name in the target category. Verify the generated suffix, original file, new text, encoding, editor position, and undo history. Try an invalid name and an unwritable store and verify the sheet keeps both inputs and the open document stays available.
- Open the Scratches sidebar in a folderless window and in a folder window. Verify that Global and two projects with the same basename can be distinguished and expanded. Click a file, then add a file with Command-click or a range with Shift-click. Verify focus stays on the outline. Open a scratch from a collapsed category with ⌘P and verify it is revealed and selected.
- In a new window without a folder, press ⌘B and check that **Scratches** opens and appears directly below **Worktree** in the menu. Switch to **Search**, hide the sidebar, and reopen it, including after a session restore. Verify that the window remembers **Search**.
- Drag two selected scratches to another project, Option-drag one to copy it, and move a scratch with **Choose Folder…**. Cancel one move and simulate a failed move. Rename or move a project on disk, then reassign one of its scratches and verify its text, editor state, and pin survive. Exercise inline rename and Trash with Undo and Redo. Verify that the category creation menu offers **New File…**.
- Open an ordinary file, save a scratch, then open another ordinary file. With an empty ⌘P query, verify that the scratch appears between them. Pin the scratch to put it first, unpin to restore its position, and reopen it to promote it by recency. Compare empty and filtered queries in different folders and without a folder. Check the icon beside the pin and the scope after moving a scratch.
- Edit a scratch and verify that it saves after the idle interval and immediately on focus loss. Verify that edits made while the first scratch write is pending also autosave. Close or replace the buffer, quit, and reopen the scratch from the sidebar or Go to File. Verify its latest text and category. Repeat with a write failure and check recovery of the unsaved edits. Use **Save As…** and verify the new file opens as a regular file while the scratch remains available.
