# Markdown preview

## Entering and leaving preview

**Markdown: preview** in [Control Command Mode](../control-commands/spec.md) and the View menu toggles the document area between source and rendered Markdown in the same window. Make the command available whenever the current text buffer's effective [syntax mode](../syntax-highlighting/spec.md) is Markdown, including manually selected Markdown on an untitled draft and read-only text from [Jujutsu history](../jj-source-control/spec.md). The preview renders the current buffer, including unsaved edits, and uses the same document title, sidebar, and terminal. Prepare the render in the background, discard superseded results, and keep the visible document paired with its title and buffer revision.

Use the same [glass document header](../../design.md#document-header) in source and preview. Start rendered content below the controls at the top of the scroll range, then let the page pass visibly under the glass. Keep the document's read-only and conflict controls in that header when they apply. Restore the prepared page and its reading position with the corresponding filename and status.

Focus the preview on entry. Render selectable, copyable prose in a readable column that follows the current light or dark appearance and fits narrow windows. Allow overflowing tables and code blocks to scroll horizontally. Links and disclosure controls work with the pointer and keyboard and have accessible names. A render failure shows an inline explanation and leaves the toggle and Escape available.

Escape exits when the preview has focus. A menu, sheet, palette, or search field with an interaction to dismiss handles Escape first. Both exit paths focus the editor and restore its scroll position, selections, carets, and [Focus](../focus/spec.md) scope. Rendered prose is selectable. Task checkboxes are the editing surface in preview for writable buffers. Save, Save As, autosave, and pending-save handling use the normal [file flow](../files/spec.md). Source editing commands, including Replace, are unavailable in preview. When the effective syntax changes away from Markdown, return to source. An external reload follows the normal clean-buffer rules and updates preview in place.

## View state

Remember editing or preview mode and the preview's reading position alongside the source editor position. Each open window has its own state, including when two windows show the same file. On ordinary file switches and reopens, use the window's remembered state for that file when available. Otherwise use the most recently recorded state from [recent file positions](../files/spec.md#open-and-save). Equivalent paths follow the existing file identity rules. Restore each open window's own state on app relaunch. [Reopen Closed File](../reopen-closed-file/spec.md) restores the mode and position captured on close. Older saved positions default to editing. If the file changes on disk, keep its saved mode when it is still eligible and clamp the positions to the new content.

On first entry without a saved reading position, show the rendered block nearest the top visible source line. Subsequent toggles restore the preview's last position and the editor's own position independently. Preserve the preview's reading position as closely as possible when its layout or content changes. Store disclosure choices with the reading position and restore them on toggle, reopen, and relaunch. Use the source's initial state for disclosures with no matching saved choice. Draft restoration uses the draft's own view state. A historical file's preview state belongs to its repository, revision, and path.

## Rendering

- Render CommonMark headings, paragraphs, emphasis, lists, ordinary and nested quotes, inline code, code blocks, rules, links, and images. Include GFM tables, strikethrough, extended autolinks, and nested task lists. Render `[ ]`, `[x]`, and `[X]` as checkboxes. When the source is writable, activating a checkbox edits its task marker in the current buffer as one undoable operation and follows normal dirty-state and autosave behavior. Preserve scroll and selections and let Undo and Redo update the checkbox in preview. Revalidate the task against the current buffer revision before applying changes. Read-only documents, including Jujutsu history, display disabled checkboxes. [GitHub Flavored Markdown specification](https://github.github.com/gfm/)
- Render `<details>` and `<summary>` as interactive disclosures. Respect the `open` attribute, support nested Markdown inside the disclosure, and use a default label when the summary is absent. [GitHub collapsed sections](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections)
- Color fenced blocks with the existing [syntax highlighting](../syntax-highlighting/spec.md) and recognized language identifiers. Render unlabelled blocks and blocks with an unknown language as selectable monospaced text. [GitHub fenced code blocks](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-and-highlighting-code-blocks)
- Render GitHub alerts for `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, and `CAUTION`, with a recognizable label and icon. Number footnotes by first reference and place their definitions at the end. Each reference jumps to its note, and return links lead to the corresponding references, including repeated references. Preserve multiline definitions. Generate GitHub-style heading anchors, including suffixes for duplicate headings, and honor explicit `<a id>` and `<a name>` anchors. Expand recognized GitHub emoji shortcodes in prose. [GitHub writing syntax](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)
- Render Mermaid fences as diagrams and GitHub-style LaTeX math in inline and display forms, including `math` fences. Use local rendering assets. If rendering fails, show the original diagram or formula source at that location. [GitHub diagrams](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams) · [GitHub math](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)
- Support safe HTML formatting, including emphasis, line breaks, keyboard and sample text, subscript and superscript, lists and definition lists, tables, figures, links, and images with alternate text and dimensions. Allow presentation and link attributes by element. Keep document-provided scripts, stylesheets, event handlers, and embedded pages inert. Route HTML links and image sources through the same resolution and loading policies as Markdown links and images. [GitHub rendering pipeline](https://github.com/github/markup)
- Display local images inline with alternate text available when the image cannot be displayed. For an unseen remote image URL, display its alternate text and a control to load it inline on click. Remember explicitly opened URLs locally and load those exact URLs automatically when encountered again. Apply the same rule to images rendered through HTML or other Markdown extensions.

## Links and search

- Click a link in preview to follow it. In source, hold Command and click the text or destination of an inline or reference link, an autolink, or a footnote reference. Hovering over a link shows its destination, including any fragment. Footnotes and their return links show the note or reference they lead to. Show a pointing hand over an actionable source target while Command is held. An ordinary click keeps its editor selection behavior. Link-like text inside code spans and blocks stays literal.
- A same-file fragment scrolls to its target in preview or reveals the corresponding source position in the editor. In preview, expand any disclosure containing the target. In source, Command-click a footnote reference to reveal its definition. Command-click the definition label to return to its originating reference, or the first reference when there is no recorded origin.
- Open a different local Markdown file in the same window in the mode the link was followed from. A link from source goes to source. When following a link from preview, keep the current rendered document and title visible while preparing the destination. Replace both together once the destination preview is ready to draw. An explicit `#fragment` takes precedence over the destination's saved position and is applied before the first frame. If the fragment is missing, keep the current position for a same-file link or use the destination's saved position on a file switch, and indicate that the target was not found.
- Resolve relative links and images from the source file's directory, including `../` and percent-encoded names. Resolve leading-slash paths from the repository root when available, or the current folder when there is no repository. For an untitled draft, use the window's folder as its directory when one is open. If the draft has no folder, same-document fragments, external URLs, and explicit local `file:` URLs can still resolve. Use `file:` URLs for explicitly absolute filesystem paths. In Jujutsu history, resolve repository-local targets in the displayed revision. A missing target in that revision leaves the source visible and reports the error. [GitHub relative links](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#relative-links)
- Route local non-Markdown text to the editor and other local file types through the normal Edit open flow, including the existing media preview. Missing or unreadable destinations leave the current file visible and show a short error. A canceled save or open leaves the originating mode and position intact. Open external web and mail links through the system handler on activation.
- Record file switches and successful anchor or footnote jumps in [navigation history](../navigation-history/spec.md). Go Back and Go Forward restore the originating or destination mode and position. Toggling preview by itself creates no navigation stop.
- Command-F in preview searches rendered text that is currently visible or reachable by scrolling. Keep preview Find independent of source Find and Replace settings. Dismissing preview Find returns focus to the preview.

## Acceptance

- Edit a Markdown file, select text with several carets, scroll on both axes, and open preview from Control. Check that unsaved text renders. Exit using Escape and again using the same command. Check editor position, selections, Focus, dirty state, and undo history. Repeat with a palette open when first pressing Escape and with a non-Markdown file when invoking the command.
- Scroll in source, enter preview, and check that the first rendered block corresponds to that position. Change the reading position and expand a disclosure. Switch away, reopen, and repeat through Close, Reopen Closed File, and relaunch. Restore two windows showing the same file in different modes. Open an older saved position and a Markdown file changed on disk. Repeat previewing and restoring with an untitled draft in Markdown syntax mode.
- Render a fixture with nested checklists and disclosures, a table, images, both highlighted and plain code fences, nested quotes, every alert, duplicate headings, a multiline footnote referenced twice, an emoji shortcode, safe HTML, Mermaid, and inline and display math. Check light and dark appearance, narrow resizing, keyboard disclosure and link activation, and copying text. Verify the renderer's treatment of malformed markup and executable HTML. Check that an unseen remote image URL is requested only after activation and that reopening can load that URL again.
- Toggle a task, undo and redo from preview, and inspect the source, dirty state, and autosaved bytes. Repeat in an untitled Markdown buffer and check that tasks in a historical revision are disabled.
- Follow ordinary links, a relative link into another Markdown file with a heading fragment, a repository-root link, and a link to a different file type. Exercise percent-encoded paths, missing targets, a canceled file switch, and a fragment inside collapsed details. Use history in both directions. In source, exercise Command-click on all supported link forms, jump to a footnote and back, and check ordinary selection and literal code spans. Follow a historical link whose destination differs from the working copy and check that the displayed revision supplies the destination.
- Hover over an external link, a relative link with a fragment, and a footnote in preview and in source. Check their destination tooltips. Hold a local preview link's destination pending in the isolated app and check that the originating title and preview stay visible. Release it and check that the destination title and preview appear together, already at the requested fragment, with no intervening editor surface.
- Use Command-F in preview, return through Escape, and check that the source Find and Replace state survives the round trip. Switch between two Markdown files while rendering and verify that no result from the previous buffer replaces the current view.
