# Editor

A new untitled Edit window opens with a focused, empty plain-text buffer and one caret. [Files](../files/spec.md) defines how to open, save, and restore documents. The system supplies the window title bar, traffic lights, menus, scrollbars, caret, and selection appearance. AppKit and TextKit 2 handle text input and layout.

Use Menlo Regular at 12 points with an 18-point line height, matching the default editor typography in VS Code on macOS. Show the caret and highlight its current line across the viewport while the editor has focus in the key window. When focus leaves the buffer, keep its selections visible in the inactive selection color. Use a single text surface that follows macOS appearance. By default, lines can extend beyond the viewport and scroll horizontally. [Toggle Word Wrap](../word-wrap/spec.md) fits lines to the editor width for the current file. Both axes use native macOS scrollbar preferences. Resizing the window or a split pane preserves the viewport relative to the exposed edge, within the available scroll range.

## Editing

- Type and select Unicode text with the keyboard, mouse, or macOS input methods. Use native character movement, page navigation, and key bindings. Option-Left/Right use the default macOS [VS Code word commands](https://github.com/microsoft/vscode/blob/661626d0e72f97806550790a98fb87116c9db825/src/vs/editor/common/cursor/cursorWordOperations.ts): skip spaces and tabs toward the previous run's start or next run's end, and treat adjacent punctuation as a run. A lone separator next to a word can share the word's stop in the direction of travel, except when moving left with multiple carets. At a logical line edge the same command searches the adjacent line; an empty or whitespace-only line still has a stop. Shift keeps each anchor and moves only the active end; without Shift, the move starts from that same active end and clears the selection.
- Option-Delete and Option-Forward Delete use the same character classes, but do not skip a lone separator. Backward deletion removes a run of at least two spaces/tabs on its own; forward deletion removes any adjacent run of spaces/tabs on its own. From the start of a line, backward deletion removes just the newline. From the end of a line, forward deletion removes the newline and any indentation on the next line.
- Double-click word selection uses the same character classes as Option-Left/Right. In `playdate_mod.getEmittedDocs()`, the dot separates the two names and the underscore stays inside `playdate_mod`. The position immediately after a word selects that word. Inside a run of separators or spaces and tabs, select that run. After the second click, dragging into the interior of another word extends to that word's far edge. These rules also apply in expanded inline diffs. [VS Code word selection](https://github.com/microsoft/vscode/blob/661626d0e72f97806550790a98fb87116c9db825/src/vs/editor/common/cursor/cursorWordOperations.ts#L683)
- Consecutive Up and Down commands preserve a single caret’s horizontal position when a short line can only show it at the end. A later vertical move returns to that column when the line is long enough.
- Escape closes expanded inline changes first. Otherwise it keeps only the primary selection when there are multiple carets, or collapses a single selection to its active end. The text stays intact.
- Use the Edit menu or Command-X, C, V, A, Z, and Shift-Command-Z for Cut, Copy, Paste, Select All, Undo, and Redo. Copy and Cut with an empty selection act on the current line. Pasting a whole-line copy at a caret inserts it above that line. Selected text uses native clipboard behavior.
- [Smart Typing](../smart-typing/spec.md) defines delimiter insertion, wrapping a selection, Return indentation, and Tab stops. Shift-Tab outdents the affected lines.
- Option-Up and Option-Down move the current line or selected block up or down and keep the selection with the moved text. Undo restores the original line order and caret or selection. At the document boundary the block stays in place.
- Command-Return inserts below and Shift-Command-Return inserts above with matching indentation. Command-] and Command-[ indent or outdent each affected line using the file's indentation settings. Outdent removes one leading tab or up to one indentation level of leading spaces.
- Command-Delete deletes the prefix of a line, and Command-Forward Delete deletes the suffix. At the relevant line boundary these commands join adjacent lines.
- Command-= and Command-- change the text size by one point, from 6 to 72. Line height is 1.5 times the font size, rounded to a whole point. Command-0 and a fresh launch restore 12 points. Zoom keeps the same line at the top of the viewport. If the active line was visible and moves outside the viewport, scroll just enough to show it again. Keep the selection and leave offscreen carets in place.

The Edit menu groups line commands in the Lines submenu. The View menu offers text sizing and native full screen. The Window menu offers Minimize, Zoom, and Close Window. The Help menu uses macOS command search.

## Acceptance

- Open a new untitled window and start typing. Select and replace Unicode text and use native undo and redo.
- Exercise indentation, inserting and moving lines, boundary deletion, and whole-line clipboard behavior. Undo each discrete line edit.
- Move a line in each direction with an empty selection and move a block with an existing selection. Undo and Redo each move and check the text and caret or selection.
- Open a wide and tall sample within the scratch buffer. Confirm native horizontal and vertical scrolling and active-line highlighting. Shrink and enlarge the window with the caret outside the visible part of a long line. Check both axes from the left edge and after scrolling, with the sidebar open and closed. Scroll deep into the buffer and zoom out and in. Check that the viewport stays painted, the window keeps its size, and the top line stays in place. Select text near the lower edge, then zoom in enough to move that line outside the viewport. Verify the selection returns into view.
- Move the caret between rows before and after horizontal scrolling. Check that the highlight runs across the current row even when the caret is beyond the horizontal edge, and that previously highlighted rows stay clear as more of the document comes into view. Overscroll past each horizontal edge and confirm that the row stays highlighted across the exposed space.
- Move focus to a sidebar and another window. Verify that carets and the current-line highlight disappear immediately, existing selections keep the inactive color, and returning focus restores the caret-driven display. [AppKit insertion point drawing](https://developer.apple.com/documentation/appkit/nstextview/shoulddrawinsertionpoint)
- Run `./script/check` to exercise native editing and render the implemented buffer without stealing focus.
