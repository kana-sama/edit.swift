# Zig language server

Edit connects to ZLS to show symbol documentation and navigate Zig code. This slice covers **Go to Definition** (`textDocument/definition`), **Find All References** (`textDocument/references`), and **Hover** (`textDocument/hover`). [LSP checklist](../../lsp-checklist.md)

## Server discovery and session

- `zls` is the built-in server for Zig. Discover it in the window's folder from `build.zig`, `build.zig.zon`, or loose `.zig` and `.zon` sources. Check nested directories in an opened folder and skip hidden folders and generated output. Recheck when the folder changes. Without an explicitly opened folder, use the document's containing directory and any enclosing Zig project.
- Find the first executable named `zls` in `PATH` order. For a Finder or Dock launch, resolve `PATH` from the user’s login shell on demand, with the inherited `PATH` as the fallback if the lookup fails. Pass the selected `PATH` to ZLS so it can find Zig. Search only the directories in that `PATH`. Show **Not on PATH** if the search finds no executable. [Zig and ZLS compatibility](https://zigtools.org/zls/install/#zig--zls-version-compatibility) · [VS Code shell environment](https://code.visualstudio.com/docs/supporting/faq#_resolving-shell-environment-fails)
- Start a recognized project in the background. For a Zig file, use its nearest project root within the open folder, or the folder for loose sources. A non-Zig file or an empty editor in the same folder keeps the project controls available. Send document text and symbol requests for named, editable Zig buffers. Initialize ZLS with the project root in `workspaceFolders`.
- A session belongs to the current window and project root. Reuse it when navigating between Zig files in that root. Close the previous session when changing roots or closing its window. An explicit stop suppresses automatic starts for that window and root until **Start LSP** or **Restart LSP**, including when returning to the project during the same app session.
- Send the actual buffer text on open and keep it synchronized before requesting symbol information. Use ZLS’s advertised synchronization mode and negotiated position encoding, including UTF-16 by default. On a file switch or Save As, close the old document URI and open the new eligible URI. On restart, send the current buffer, including unsaved edits. [ZLS initialization and capabilities](https://github.com/zigtools/zls/blob/0.17.0/src/Server.zig#L320-L523)

## Header and controls

Place an icon-only Language Servers button at the right edge of the document header. Show it when the folder has at least one recognized project. The glowing dot is green when all applicable servers are ready, red when all are stopped, unavailable, or failed, and yellow for partial readiness or a start or stop in progress. Use the tooltip and accessibility label to expose the server state.

Open a native popover from the button. Each compatible server has one row with its language icon and name on the left. Group two equal-sized icon controls close together at the right edge, vertically centered with the server name. Play starts or retries the server. Stop replaces Play in the same position while the server is starting or ready. Restart resolves the executable again and starts a fresh session. The control labels and tooltips identify the actions. A failed server exposes its reason through the row tooltip.

Expose **Start LSP**, **Stop LSP**, and **Restart LSP** in [Control](../control-commands/spec.md). Keep the folder button and controls available while viewing a non-Zig file in a recognized project. Escape dismisses the popover. [AppKit popover](https://developer.apple.com/documentation/appkit/nspopover)

## Cmd-hover and Cmd-click

Follow VS Code’s definition link gesture on macOS. When the pointer rests on a symbol with Command held, including when Command is pressed under a stationary pointer, probe with `textDocument/definition`. Once the current probe resolves to an actionable target, underline the source span, use the semantic link color, and show the pointing hand. Use `originSelectionRange` if the server returns it, or the word under the pointer otherwise. Release Command, leave the symbol, or change the document to clear the link. Plain clicks and drags use the normal editor selection behavior. [VS Code link gesture](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts) · [Definition link and probe](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/gotoSymbol/browser/link/goToDefinitionAtPosition.ts)

Cmd-click on the link sends a fresh `textDocument/definition` request at the clicked position. Accept both `Location` and `LocationLink`, using `targetSelectionRange` for a link’s destination. Treat the sole definition as the current location when it is in the same file and its selection range contains the clicked position. This also applies when the click is inside the name rather than at its first character. [VS Code navigation and fallback](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts#L111-L201)

- A single definition elsewhere opens directly. Use the normal file-opening and save flow for a destination in another file. Place the caret at the start of the returned selection range and reveal the line if it is outside the viewport.
- A sole definition at the clicked location invokes **Find All References** if the server advertises it.
- Several distinct definitions offer a source-anchored **Peek Definition** choice, following VS Code. Open the selected destination using the same file-opening and caret rules.
- An empty response keeps the editor at the source and clears the link. A failed explicit navigation can show feedback without moving the caret.

Ignore pending lookups when their server session, source document, buffer version, or relevant pointer position changes. A delayed reply must not decorate a different symbol or open a file after the user has moved on to another document.

## References in the sidebar

Use VS Code’s compact reference lookup. Send `textDocument/references` with `includeDeclaration: true`. If the server returns exactly two locations, retry with `includeDeclaration: false` and use the retry if exactly one location remains. A single result opens directly at the start of its range. Zero results leave the editor at the source and briefly show **No references found**. Multiple results open **References** in the sidebar. [VS Code 1.147.0 compact lookup](https://github.com/microsoft/vscode/blob/1.147.0/src/vs/editor/contrib/gotoSymbol/browser/goToSymbol.ts#L67-L77)

- Use the [Search results](../find-replace/spec.md) component for file headings, result rows, keyboard and click handling, and editor match decorations. Show the symbol and result count. Sort groups by file path and hits by line and column.
- Keep every file group open. Align the file icon and name to the left of result excerpts. File headings are labels that stay outside the selection order. Highlight the exact range returned by the server in each single-line excerpt.
- Initially select the nearest hit in the originating file, or the first hit. Click or use the arrow keys to preview a hit in the editor while focus stays in References. Scroll to and highlight the location, including when the selected hit is in another file. Skip file headings when moving across groups.
- Space or Return gives focus to the editor at the selected hit and leaves the reference list available. An activated result enters [navigation history](../navigation-history/spec.md). Moving through the list previews results without adding a history stop for each one.
- Make References available from the [sidebar switcher](../sidebar-menu/spec.md) while the window has a result set. Command-F returns to Search with its own query. A new reference lookup replaces the previous set together with its symbol and count.

## Hover

After the pointer rests on a symbol for 300 ms, request `textDocument/hover`. Show a nearby popover for a nonempty response, preferring space above the symbol and using space below when needed. Anchor it to the server’s hover range when supplied. Point the popover’s arrow at the center of the highlighted symbol with a gap between the tip and the text. Keep the arrow aimed at the symbol when the popover shifts away from a screen edge. Reduce the visible height when space is limited. Keep Command-link decoration independent of the documentation popover. [VS Code hover defaults](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts#L2304-L2313)

Render Markdown as selectable rich text with paragraphs, lists, links, inline code, and fenced code blocks. Use the editor’s code styling for recognized code fences, the system appearance for prose, and scrolling for content that exceeds the available space. Show plain-text responses as text. Keep the popover open while the pointer moves into it to read, select, copy, or follow a link. Dismiss it on Escape, typing, document changes, or after the pointer leaves both the symbol and the popover. [VS Code hover interaction](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/hover/browser/contentHoverController.ts) · [VS Code Markdown hover](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/hover/browser/markdownHoverParticipant.ts)

For recognized ZLS responses, lead with the selectable, syntax-highlighted declaration on a lightly tinted background and place the Markdown description directly below it. Give both bodies accessible names. When metadata is available, add a native divider and show **Type** and **References** below it. Right-align those labels in the secondary label color and align each with the first line of its content. Use a common left edge for all section bodies. Render declarations and types in code blocks with the same background, padding, and normal code line height. Omit rows with no corresponding data. Keep types selectable and syntax-highlighted and list references as comma-separated links. Dedent declaration continuation lines and remove the single pair of parentheses ZLS wraps around each type. Preserve alternative types, type values, and ZLS’s truncation marker. [ZLS symbol hover formatter](https://github.com/zigtools/zls/blob/master/src/features/hover.zig#L140-L184) · [ZLS builtin hover formatter](https://github.com/zigtools/zls/blob/master/src/features/hover.zig#L210-L256)

Use the generic hover renderer for plain text, unfamiliar Markdown, and ambiguous responses such as combined field hovers. In generic Markdown, set fenced code directly on the popover surface. Size both presentations from their text layout with balanced padding and scroll when the content exceeds the available height.

Make the type names sent in ZLS’s `Go to` paragraph clickable in the hover’s **References** row. The server provides each destination as a local Markdown link with a `file:` URI and a one-based `#L` line number. The first click dismisses the hover, opens the decoded path in Edit, and places the caret at the beginning of that line. The first drag over selectable text starts a selection even while the editor has focus. Go Back returns to the hovered symbol. [ZLS hover markup](https://github.com/zigtools/zls/blob/master/src/features/hover.zig#L149-L165) · [VS Code line fragments](https://github.com/microsoft/vscode/blob/main/src/vs/platform/opener/common/opener.ts#L137-L159)

## Acceptance

- Open a Zig fixture with compatible Zig and ZLS on `PATH`. Verify the trailing icon and the Play/Stop and Restart controls during open, start, stop, restart, and process failure. Open a text file in the Zig folder and then in a folder with no Zig project to check when the icon appears. Switch files within the project after **Stop LSP** and check that it stays stopped. Switch to a separate fixture project and back to confirm the root and stop scope. Repeat with two candidate executables on `PATH` and with neither available.
- Hold Command over an imported symbol and then release it without moving the pointer. Verify the link color, underline, and pointing hand appear for the actionable span and clear on release. Check a non-symbol, a pending result that arrives after moving away, and clicks at the beginning and middle of the same symbol.
- Cmd-click a definition in the same file, one in a separate file, and a declaration with exactly one use. Verify the first two open the definition and the last opens the use directly. Add another use in a third file and verify References opens in the sidebar with grouped, highlighted excerpts and the correct count. Click a hit and move across a file heading with the arrow keys. Check that each action previews the hit while list focus remains. Use Space and Return to focus the editor.
- Run Find and Replace before and after opening References. Verify Search retains its query and row actions, both panels still highlight their own exact spans, and resizing the sidebar keeps excerpts on one line.
- Hover over a symbol with a signature, formatted documentation, and a fenced code block. With focus still in the editor, select text with one drag and copy it. Check light and dark appearances, then dismiss the popover with Escape. Repeat after editing the buffer or switching documents before the reply arrives and verify the stale popover stays closed.
- Compare a single-line signature and a multiline declaration. Check that fenced lines have continuous line spacing and that the popover hugs the content with balanced padding.
- Compare the label and content column edges on short and wrapped rows. Move the same hover target near each screen edge and verify that the arrow points at the symbol with space between them.
- Hover over `std.log.debug`, a builtin, and a symbol with more than one possible type. Check that the declaration and description lead without visible labels and that the divider appears when labeled metadata follows. Verify that types keep their internal parentheses, referenced types appear as comma-separated links, and unfamiliar responses use the generic renderer.
- Hover over a variable with an inferred type declared in a different Zig file. Use a destination filename with spaces, a hash, and a non-ASCII character. Verify that the cursor is a pointing hand over the linked type name and a text cursor over the adjacent prose. Click the link, check that Edit focuses the declaration line, and go back to the hovered symbol.
- Place a multibyte character before a target and use a project path containing spaces. Rename or move a symbol in an unsaved buffer, restart ZLS, and verify that navigation and hover use the current text and correct ranges. Run the scenario against the locally available compatible Zig and ZLS versions in an [isolated agent instance](../../agent-testing.md).
