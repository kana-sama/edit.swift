# LSP error highlighting

Underline errors published by the active file's language server with a red wave in the editor. Draw the wave under the reported text, across each visible wrapped line. For a point diagnostic inside a word, underline the whole word, following [VS Code's marker rendering][vscode-markers]. At punctuation, whitespace, or the end of a line, show a short wave at the reported position. Preserve the reported range, syntax colors, selection, and text geometry. The LSP Highlighting switch controls semantic colors independently of these marks.

Tint the last visual row of a source line with errors, including the space exposed during horizontal overscroll. Use the [Error Lens 3.30.0 line treatment][error-lens], with a faint full-row tint and red message text starting four monospace columns after the code. On a light background, use a deeper red for contrast. Keep the message and underline visible over text selections. Show the first message in reading order, followed by a spaced `+N` for the remaining errors. With Word Wrap off, lay out the full first message in document coordinates and include it in the horizontal scroll extent. With Word Wrap on, use the remaining space for a single-line preview with an ellipsis and keep the count at the end. Keep the underline and hover when there is too little room for the preview. Keep the summary outside the buffer and text layout so it preserves editing, wrapping, and row height. [Helix end-of-line diagnostics](https://github.com/helix-editor/helix/blob/master/book/src/editor.md#editorinline-diagnostics-section) · [Error Lens scroll and Word Wrap](https://github.com/usernamehw/vscode-error-lens/issues/56)

Hover an underline to read the error at that location. Where underlines overlap, choose the narrowest displayed range and use source order for ties. Hover the inline lens to read all errors on its source line. Use a neutral anchored card with a red error icon and selectable text on each row, and separators between the rows. Wrap long messages within their rows and scroll the list when it exceeds the available screen height. Point the arrow at the edge of the lens or underlined text directly above or below the pointer's position when the card opens, including after horizontal scrolling. Command-hover keeps symbol documentation and navigation available. Clear obsolete cards with their diagnostics.

Use [`textDocument/publishDiagnostics`][publish] for named, editable files. Render Error diagnostics and entries without a severity, which the protocol leaves to the client. Warnings, information, and hints are outside this feature's scope. Map UTF-16 positions against the synchronized document and discard invalid ranges. Each report replaces the previous marks, including reports with an empty list.

The [Worktree error indicators](../lsp-worktree-diagnostics/spec.md) also reflect publications for files outside the active editor.

Apply versioned reports only when their URI and version match the active synchronized document. For servers that omit the version, associate the report with the synchronized revision at receipt. Discard queued updates if the buffer changes before display. Clear marks when text changes, when the replacement document is installed, or when the server stops, restarts, or fails. While another file is opening, keep the outgoing marks with its text and title.

## Acceptance

Run `./script/check --only lsp-diagnostics` with ZLS, SourceKit-LSP, and OLS available. The isolated native check verifies live diagnostics for Zig, Swift, C, and Odin. It checks UTF-16 offsets, the expanded second `let` in `let let = 1; let`, single-error hover over code, the list over the lens, and arrow alignment after horizontal scrolling and pointer movement during the hover delay. It also checks selection paint, both horizontal overscroll edges, Word Wrap, recovery after edits and server controls, and the outgoing and incoming presentations of a held file transition. Protocol fixtures cover empty, filtered, stale, unversioned, and unrelated reports.
