# Jujutsu text conflicts

Show materialized conflicts where the user is already editing or inspecting a file. Confirm each block against the recorded Jujutsu file so that marker-like text in ordinary files keeps its ordinary meaning. Support `diff`, `snapshot`, and jj's `git` markers, long delimiters, conflicts with any number of sides, and files with no terminating newline. Show supported blocks even when another block has incomplete markers. [Jujutsu conflict formats](https://docs.jj-vcs.dev/latest/conflicts/#conflict-markers)

Use a full-width violet band and ordinary text color on structural markers. Use green text for added lines and red text for removed lines on the editor background. Shade only the changed spans within those lines, using the inline diff comparison. Preserve ordinary syntax colors elsewhere and keep the [gutter and scrollbar conflict marks](../jj-change-indicators/spec.md).

Place conflict controls at the trailing end of the document area in the shared [glass header](../../design.md#document-header). Keep previous, current/total, and next together in a compact inline group. Use the shared [mode selector](../../design.md#mode-selectors) for **Diff** and **Snapshot** when they fit. Keep the same selector in place during a format change, including in read-only revisions, so the highlight slides from the old format when the new text appears. When space runs short, switch to a menu containing only those two formats. Keep the navigation group inline. Place per-block actions at the trailing edge of the viewport and vertically center them on the entire violet section header, including adjacent opening or continuation rows belonging to that header. Scroll actions with their text in the same frame. A historical preview offers highlighting, navigation, and format switching.

Verify working-copy conflicts against the recorded file before presenting a new buffer. Publish its navigation and format controls with the first frame, without changing the header height or viewport. Preserve the text position when the live repository observer supplies its analysis.

- Show added, removed, and context rows as their original text, including indentation and blank lines. Omit the initial jj serialization prefix from the editor buffer so selection, copying, and keyboard navigation use the same text. Keep section markers, their structural line endings, and reference text selectable and copyable. Reject edits that touch them, including selections that cross from editable text into protected text. Ordinary files with literal markers retain regular editing.
- Edit the first full snapshot in the block directly. Typing at the insertion point of an empty snapshot adds its editable text and retains the separator above the following marker. Other snapshots provide reference text.
- Place one **Apply Diff** button on each diff marker. After a successful application, disable that same button in place. Keep the applied state with the pending result when the session is restored. Ordinary Undo reverses the text edit and enables its button again. A diff that overlaps the result shows **Can't Apply** in red on that same button and keeps the viewport in place. If the editable snapshot is visible, move the caret there for a manual edit. Clear the failure feedback on an edit and allow another attempt.
- Place **Mark Resolved** on the editable snapshot marker. It replaces the entire block with the current snapshot. Undo restores the protected block and its pending result. Reuse the controls as text and tracked offsets change, keeping their widths and trailing alignment stable. The closing marker and reference snapshots carry no actions.

Place the **Dim resolved** toggle immediately left of the format control in Diff mode. Match the selector's corner radius. Center the half-filled contrast symbol and its label as a group with equal end padding and a compact gap. Center the symbol by itself at the narrowest width. Give the toggle a tooltip describing its effect and keep its accessible name through compaction. The toggle defaults to off. In editable diff conflicts it dims context rows and portions of the reference patches whose effects are visible in the current snapshot. Keep unresolved spans bright and dim a whole row once its changes are accounted for. Match edits at the corresponding location relative to each diff's base, including whole replacement words surrounded by other separate words. Leave ambiguous or rewritten changes visible for review. Recompute after typing, Apply Diff, Undo, and Redo while keeping text, scrolling, and controls in place. The toggle stays available while an edited snapshot prevents switching formats.

When Diff is ready, slide **Dim resolved** out to the left from beneath the format control over 160 ms. When Snapshot is ready, slide the toggle back under that edge and reclaim its space. Keep the format control anchored and let the navigation group make room and close the gap. Clip the moving toggle at the format control's leading edge and make it unavailable as soon as Snapshot appears. Show the settled header immediately on open and whenever Reduce Motion is enabled.

Save and autosave write ordinary edits and resolved blocks while preserving the original materialized payload and diff prefixes of each unfinished conflict. Recover unfinished inline results with the session. Keep the current representation while an inline draft is edited so its starting snapshot and reference diffs stay together. Suspend actions while analysis is stale and verify the exact protected block before replacing a range.

A format change prepares the new marker text and highlight ranges together before replacing the visible block. It rewrites confirmed blocks as one undoable buffer edit, preserving their sides, bases, surrounding text, and final newlines. Preview format changes are in memory. Neither operation changes the repository configuration.

## Acceptance

- Open a real three-sided merge with two conflicts from a regular file. Check that the first frame pairs the header controls with the file and that the first line stays in place when the live analysis arrives. Check marker bands, diff glyph colors, local word highlights, and floating buttons in both appearances. Check the button center on one- and two-line headers and verify that the button moves with the band immediately during scrolling. Navigate to the next conflict and switch formats by clicking the empty space around each segment label. Check that the highlight slides from the previous choice, gently springs into place, and stays within the track. Switch formats from the compact menu as well. Check that Dim slides out and back without moving the format control. Check that Snapshot clears the previous colors from ordinary text on the first frame. Resize with a long filename and verify the shared header’s compaction order.
- Toggle a line comment in a conflicted source file and undo it. Check that syntax colors on the surrounding code stay attached to their text in the first frame after each edit, before analysis returns.
- Reject typing, multiline replacement and input composition across a confirmed marker. Apply an overlapping diff and check that its button shows the failure without moving or scrolling the view. Edit the snapshot in the same editor and verify that **Apply Diff** returns. Save while resolving and confirm jj still sees the original conflict. Apply both independent diffs in the other block. Verify the buttons keep their positions and a second click cannot repeat a successful patch. Undo one application and verify that only its button becomes active again. Mark the result resolved and check that Undo restores the original protected block and its draft.
- Snapshot a format-only edit with jj and verify that it preserves the recorded conflict, including sides with different final line endings.
- Open the same conflict in another revision. Switch its format and verify the preview remains read-only and the working file stays unchanged.
- Select and copy several added, removed, and context lines in a working conflict and a read-only revision. Check that the copied text starts with the actual content or indentation and includes empty context lines. Save and reopen the unresolved file and verify jj still recognizes the conflict with its original prefixes on disk.
- Turn on **Dim resolved** and copy only one of two word replacements into the snapshot. Check that just the corresponding pieces dim on both sides of the diff. Check a whole-word replacement with an added prefix word and a separately changed number on the same line. An inserted term followed by another additive term at the same location dims. A changed number or multiplier within the original term stays bright. Apply or manually reproduce an inserted or removed line and confirm its whole row dims. Undo and redo an edit and check the current snapshot controls the shading in both directions. Check context rows dim and unrelated occurrences stay bright.
