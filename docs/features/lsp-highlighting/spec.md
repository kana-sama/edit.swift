# LSP highlighting

Edit renders semantic tokens over the [Tree-sitter colors](../syntax-highlighting/spec.md) in named source files served by an active language server. When both layers are enabled, the semantic token wins at each overlap and the underlying colors fill gaps in the server's coverage. Tree-sitter supplies the opening and editing colors independently of the server. Files outside a supported server's scope, read-only previews, and buffers with projected conflict edits can use the Tree-sitter layer. Plain Text stays uncolored.

**Toggle Tree-sitter Highlight** and **Toggle LSP Highlight** in [Command Mode](../control-commands/spec.md) and the View menu control the layers independently. Both default to on. Each setting applies immediately to open windows for that folder and is saved across launches. Standalone windows share a separate pair of settings. Other language-server features and Tree-sitter bracket analysis stay available.

Request whole-document tokens as soon as a server is ready for the open file. When ZLS supports both modes, a file is at least 64 KiB, and the viewport covers a small part of it, also request the visible lines. Apply the range result when it arrives first and replace it with the whole-file result for scrolling. SourceKit-LSP performs file-wide semantic analysis for a range request, so request the whole file once. Use deltas when the server supplies a result ID and supports them. For a range-only server, request the document range.

Coalesce edits before asking for fresh tokens. Keep remapped overlay colors on unchanged tokens while the replacement is pending, up to a fixed deadline. This includes words next to a separator edit when their boundaries remain distinct. When typing extends or Backspace shortens a bare identifier whose boundaries remain distinct, carry its previous color over the entire new range temporarily. A fresh Tree-sitter classification replaces the temporary semantic color even when their ranges are identical. A fresh semantic result replaces the old overlay. Discard the whole old range when an edit otherwise changes a token or can join it with a neighbor. A stale range cannot recolor part of a token from a fresh result. Clear the overlay when switching files or losing the semantic provider. Decode tokens off the UI thread and discard results from an old revision or connection.

Map server token types and supported modifiers to the existing Edit theme. Follow the [shared rules for Tree-sitter and semantic tokens](../syntax-highlighting/spec.md#tree-sitter-and-semantic-tokens) when adding or updating a language integration. Request syntactic tokens from SourceKit-LSP for Swift as well. Tree-sitter remains available to bracket navigation.

## Acceptance

Open a Zig or Swift file in an eligible folder. Verify that the layers agree on syntax that both classify and that semantic tokens add color to symbols that start in the default text color. Independently toggle each layer in Command Mode and verify all four combinations, propagation to windows for the same folder, and saved settings. Hold the full result for a large Zig file and verify that visible semantic tokens arrive before offscreen tokens. During a held update or file switch, verify the visible text, title, and colors in the pending and ready frames. Hold both results and complete `erro` as `error`. Check all five glyphs in the first frame, then release Tree-sitter and verify that all five change together. Continue typing `.Hello` one key at a time and check the keyword, dot, and whole error tag before and after releasing each result. Backspace at the end, in the middle, and at the start of the tag before repeated semicolons. Verify that every surviving glyph retains the previous color in the first frame and while both results are held. Type and delete a space after `return`, delete the trailing dot in `error.`, and check that the words keep their colors throughout. Deleting the only separator between two words clears their old colors in the first frame. Use `./script/check --only lsp-highlight` for the native check.
