# Find and Replace

## Workspace search scope

Extend the existing Search sidebar with two scopes, **Current Buffer** and **Workspace**. Use the shared [mode selector](../../design.md#mode-selectors) with equal segments spanning the full field width below Find and the optional Replace row. Workspace adds two stacked, full-width, single-line glob fields with **In.** and **Ex.** labels. Use **Include** and **Exclude** for accessibility and tooltips, and describe relative paths and comma-separated syntax in the tooltips. Keep each field usable at the sidebar’s 211-point minimum width and let it scroll horizontally while editing. Hide both glob fields in Current Buffer.

- **⌘F** selects Current Buffer. When switching from Workspace it focuses Find. When Current Buffer is already active, the existing Command-F focus rules apply. **⇧⌘F** and **Edit → Find in Workspace** select Workspace and focus Find, including when the folder has no open file. Command Mode lists **Edit: Find in Workspace**. Disable the workspace entry points when the window has no folder. Closing the folder while Workspace is selected returns Search to Current Buffer.
- Choosing a scope in the picker reruns the existing query and preserves the match options. Keep the picker available whenever the window has a folder. With the sidebar hidden, Command-B restores the previous Search scope for that window. Tab and Shift-Tab reach the picker and the visible filters. Return in a filter advances to the first result when ready. Escape returns focus to the editor surface and leaves Search visible.
- **Find Here** in a Worktree folder menu opens Workspace search and focuses Find. Replace Include with a literal, root-relative glob for that folder and its descendants, such as `./Sources/Edit/**`. Keep Exclude and the query. Escape any glob metacharacters in the folder’s path so the command always targets the selected folder. Show the command for a single folder within the workspace.
- Persist both filter strings by canonical workspace folder, including an explicitly cleared field and changes made by Find Here. Reopening the same folder loads its latest saved filters. Switching to a different folder uses that folder’s filters. New folders start with both fields empty. Windows on the same folder share the saved filter values. The query, replacement text, and match options are shared between scopes within a window. Apply the existing selection-to-query behavior when a keyboard shortcut opens Find from the editor.

### Glob behavior

Evaluate patterns against slash-separated paths within the open folder. Split comma-separated patterns outside brace groups and character classes, and ignore surrounding whitespace. A blank Include admits all eligible files. Any Include match admits the path and any Exclude match removes it. A term such as `Sources` matches a file or folder of that name at any depth, including the contents of matching folders. `./Sources` anchors the same term at the workspace root. Support `*`, `?`, `**`, `{swift,md}`, `[a-z]`, and `[!a-z]`. A malformed pattern reports which field needs correction and blocks navigation to stale results.

When the workspace is inside a repository, show a small toggle inside the trailing edge of Exclude. Its accessible name and tooltip read **Respect .gitignore**. The default is on, and the workspace remembers the chosen state with its filters. Apply the applicable `.gitignore` rules, including nested files and negations. When the toggle is off, files ignored by those rules are eligible. Explicit Include and Exclude still apply in either state. Keep repository metadata out of traversal. Hide the toggle outside repositories. Find Here preserves the toggle state.

### Results and navigation

Search regular text files under the folder, using the active buffer’s unsaved text when its file is eligible. Skip unreadable and binary files and keep traversal inside the open folder. Reuse the Match Case, Whole Word, and Regular Expression controls for text matching. Search on a background task. Group results by file in relative-path order and keep each file’s matches in document order. Match the native [References rows](../lsp/spec.md#references-in-the-sidebar) for alignment, count, tooltip, and spacing. **Tree Mode** in the ellipsis menu nests file groups under collapsible folders. Each folder badge counts retained matches in every descendant file. The value stays visible while the folder is collapsed. The Tree Mode setting is independent of References and persists with the window. Use the existing sidebar interaction for revealing and opening a match. Command-G and Find Previous navigate the selected scope. Use the latest requested result when file openings overlap. Keep the old document, title, and selection together until the selected result can appear with its file title and match highlight. Discard results from stale queries, filters, or folders. Show a stable pending state for longer searches and indicate when a result limit is reached.

### Workspace replacement

- Use the existing Replace disclosure, field, and preview in Workspace. Option-Command-F opens Replace in the current Search scope. Selecting a result with Replace open previews the proposed text in the editor. Match and replacement syntax follow Current Buffer, including captures and an empty replacement.
- Offer Replace on each match, Replace All in File on each file heading, and Replace All in Workspace beside the Replace field. File and match actions occupy the existing trailing action area and appear on focus or hover. Respect dismissed matches, Include, Exclude, and the ignore toggle. Replace All in Workspace shows a confirmation with the match and file counts for the current complete result set. Disable bulk replacement while results are incomplete, stale, invalid, or truncated.
- Revalidate the affected file or live buffer against the searched revision before writing. Use the editor’s save path for open documents and preserve text encoding and line endings for closed files. If a file changed, became unavailable, or has conflicting unsaved copies, skip it and report it with any other failed files. Never overwrite a newer edit. Refresh results after the operation and keep focus in the results. Undo from the results reverses the successful replacements in one operation and reports any files it cannot safely restore after later edits. Undo in an editor continues to address that buffer’s edit history.

### Acceptance

- Open Search with each shortcut, through Command Mode, and from Worktree. Switch scopes with the segmented control at the minimum width. Verify the fields span the available width, and check focus, query retention, and the keyboard path through the fields. Toggle Tree Mode and check folder disclosure, alignment with Worktree and the Search fields, and full path tooltips. Verify file and folder badges share the trailing edge and a folder keeps its descendant count when collapsed.
- Search sibling and nested folders. Check anchored and unanchored paths, braces, ranges, commas, exclusions that override inclusions, and a literal folder with glob characters. Check that Find Here retains Exclude. Compare results with the editor’s unsaved text and verify that Current Buffer ignores the file filters.
- Verify `.gitignore` matches and negations, the toggle’s default and restored state, and its absence outside a repository. With it off, check that a formerly ignored match is visible and an explicit Exclude still removes it.
- Preview and apply a single replacement, a whole file, and the entire workspace. Verify confirmation counts and undo, including a file already open with unsaved text and a file changed on disk while confirmation was pending. Verify that dismissals and exclusions survive the operation.
- Set different filters in two folders, switch between them, then relaunch and reopen both. Check that a second window on the same folder uses the saved values.
- Select results in two files rapidly. Hold the incoming document pending and check the visible excerpt and title, then check the match and its title on the first frame after installation. Change filters or close the workspace while a search is pending and verify that stale results cannot open.

## Current buffer

Search the current document, including unsaved text, in a native AppKit sidebar. The sidebar belongs to the window, extends behind the title bar beneath the traffic lights, and can be resized. The toolbar places the [sidebar menu](../sidebar-menu/spec.md) above the sidebar and the document title above the editor. The sidebar opens and closes immediately. The editor keeps its selection and scroll position relative to the exposed edge when the sidebar opens, closes, or resizes during a divider drag. The editor draws behind the sidebar as it scrolls horizontally. Opening a result or navigating to text behind the sidebar reveals it in the exposed editor. Each window's session remembers its own query, replacement text, options, replacement visibility, sidebar width, and sidebar visibility. New windows and sessions saved before per-window Find state start with a hidden, empty sidebar.

### Search

- Command-F from outside Search shows the sidebar in Search mode. It focuses the active result for the current buffer, or Find when there is no active result or the buffer changed. After an edit, the active result follows its match or advances to the next occurrence at that position, wrapping to the first result at the end. With no matches, focus goes to Find. When opening Find input, a nonempty editor selection becomes the query. In regex mode, selected text is escaped so it matches literally. From Worktree, Command-F switches to Search and preserves the query. From anywhere within Search, Command-F focuses the editor and keeps Search visible.
- Option-Command-F expands Replace and focuses its input. Command-B closes the current sidebar or reopens its last mode, keeping editor focus when opened from the editor. Escape from either input returns focus outside the sidebar and keeps it visible.
- Find and Replace use compact, aligned fields. The Find field includes Case, Whole Word, and Regex toggles. One focus outline surrounds the active field and any toggles it contains. The buttons beside the fields expand replacement and apply Replace All. Both fields accept multiline input using Shift-Return or paste, grow while space is available, and scroll for longer text. Field undo is independent of document undo.
- Search lists one row per nonoverlapping match in document order, grouped under the filename and its icon. The fields and excerpts use the editor’s monospaced font at its default size. Excerpts highlight the matched text and truncate long lines on one row at the font’s regular character spacing. Result rows fill the sidebar with small side margins. Excerpts reach the trailing controls with a minimal gap and keep their width through hover, selection, and scrolling. The Dismiss button sits near the right edge and appears on the selected row or the row under the pointer. Replace has a reserved slot to its left in replace mode. Case, Whole Word, and Regex options apply to the current buffer. Literal whole-word search treats Unicode letters, numbers, and underscore as part of a word. Regular expressions use Foundation's ICU matcher and accept Rust-style named groups.
- Search runs in the background. Old rows remain visible while fresh results are pending. Pending rows cannot edit the buffer. Results from earlier queries or document revisions are discarded. Invalid regex disables navigation and replacement.
- Command-G moves to the next match and wraps, including when the panel is hidden. **Edit → Find Previous** moves backward and wraps. Shift-Command-G invokes Find Previous in windows without a [Jujutsu workspace](../jj-source-control/spec.md). Return in Find focuses Replace when it is open, or the first search result when there is a match. If the current query is still running, Return can focus its first result once it arrives while the originating field still has focus. Selecting a result reveals and highlights that match in the editor. Only the active match uses the active highlight. Other visible matches, including the previously active one, retain the regular search highlight. Return on a result in search mode focuses the editor and places a single caret after the match. Space and double-click do the same in either mode and clear any replacement preview. Command-F then returns to the same result when it still exists.
- Dismiss excludes one match from search navigation and replacement. An unrelated edit or replacement preserves valid dismissals. Refresh, changing the query or options, or replacing the document clears them.
- The group heading shows the file icon and name on the left and a subdued numeric count on the right. Hover over the heading to see the full path. Excerpts begin just after the filename’s leading edge. The ellipsis menu stores a Tree Mode preference for folder results. The current buffer appears as one file group.

### Replace

- Return in Replace focuses the first result and reveals its replacement preview. Moving through the results with Replace open previews each selected match in the editor using the old and proposed text on separate colored rows. The preview aligns with the surrounding text. It emphasizes the changed span within each line and temporarily reserves display space so the following source line remains visible. Clearing the preview restores the original spacing. It leaves file contents, dirty state, and undo history intact.
- Apply one result with its row button or Return on the focused row. After replacement, focus the next retained match beyond the inserted text if one exists. Replace All applies the retained matches in one undoable edit. An empty replacement removes the matched text.
- Regex replacements support numbered captures, named captures, and a doubled dollar for a literal dollar. Edits made with Find and Replace request the existing autosave.
- Escape on a result clears its selection and preview and focuses Find. Returning to the editor, collapsing Replace, refreshing, or hiding the panel also clears the preview. Clicking the same selected result again restores its preview while Replace is open.

Command Mode exposes refresh, option toggles, replacement, and result actions when the sidebar can perform them. Direct Command-B leaves an open Control palette available. Command-F and Shift-Command-E dismiss Control and apply the same panel focus shortcuts.

### Acceptance

- Search multiple matches on one line and across lines. Verify Unicode whole-word matching, named captures, and the invalid regex state.
- Use Return to move from Find to the first result in search mode, or from Find through Replace to the first result in replace mode. Verify that Return on a result focuses the editor in search mode and applies one replacement in replace mode.
- Press Command-F, Return, and Down, then open the result with Space or Return. Press Command-F again and verify that it focuses the same row. Insert text before the match, remove the active match, switch files, and remove all matches to check selection continuity and the fallback to Find.
- At the narrowest sidebar width, compare the excerpt and both row actions in Search and Replace. Scroll a long list with the pointer held still, then move it outside the list. Verify that only the selected row or the row under the pointer shows Dismiss.
- Dismiss one of three matches, replace one of the others, then Replace All. Confirm the dismissed text remains, Undo reverses each operation, and Refresh restores the dismissed occurrence.
- Select consecutive results in a syntax-colored file, then navigate to matches beyond the visible area and back. Confirm that the editor paints only the selected match with the active color. Double-click a result with Replace open and confirm that focus moves to the editor and the caret lands after the match. Verify that the preview and navigation leave the buffer unchanged and Command-G works with the panel hidden.
- With a long unwrapped line, open and close the sidebar and drag its divider. Repeat from the editor’s left edge and from a horizontally scrolled position. Verify the text keeps its position, the first column is beside the sidebar at rest, and the same text moves behind the glass when horizontally scrolled. Reveal a match from behind the sidebar and check that it moves back into the exposed area. Check that long excerpts stay on one row at the narrowest sidebar width and the next editor line remains visible during preview.
- Reopen the sidebar partway through closing, then close it partway through opening. The sidebar changes direction without jumping and reaches its previous width when reopened. Use different queries, options, replacement text, and sidebar widths in two windows. Hide one sidebar, quit, and reopen Edit. Verify that each window retains its own state. Open a new window and check that Find starts empty.
